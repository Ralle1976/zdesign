# Phase 3 (Final): Hybrid-Pipeline via Cream + Agent-Mode-Default

## 🪞 Plan-Reflexion (vollständig, 4 Linsen)

### 🔍 Experten-Linse — "Würde ein 10-Jahre-Experte das so machen?"

**Der ursprüngliche Plan war 4× zu komplex.** Fünf Vereinfachungen identifiziert:

1. ❌ **HTML→JSON-Roundtrip GESTRICHEN** — Konvertierung von 8/10-HTML zu JSON zerstört die gesamte Atmosphäre (Verläufe, CSS-States, Pseudo-Elemente). Das Design würde wieder zu 4/10. **Statt dessen:** HTML-Refinement via Cream (Infrastruktur in `generateHtmlPrompt(existingHtml?)` existiert bereits, Zeile 153 in art-direction.ts).

2. ❌ **Keine neuen Modi-Konzepte** — "Studio-Modus" und "Editor-Modus" sind neue Begriffe für bestehende Konzepte. Der Codebase hat bereits `agentMode` (Bot-Button, lokale State in ChatPanel.tsx:712) und `designMode` (globaler Store). **Statt dessen:** `agentMode` default ON für neue Projekte.

3. ❌ **Keine Pfad-Löschung** — Der alte Agent-Path (`/api/design/agent`) bleibt als MCP-Contract bestehen. Cream wird nicht "der eine Pfad" — es wird der Default für Neu-Generierungen.

4. ✅ **Quick-Mode** — Cream ohne Vision-Critique = 1 LLM-Call ~25-60s. Default, da der Vision-Loop 90-180s dauert und das für Chat-UX unzumutbar ist. Voll-Modus optional.

5. ✅ **Graceful Degradation** — Bei Puppeteer-Fehler (Produktion!) ungeprüftes HTML zurückgeben statt 500-Fehler.

**Experten-Urteil:** Von ~350 Zeilen auf ~180 Zeilen reduziert. Drei Schritte statt vier.

### 🌐 3D-Blick

- **[near]** Cream's `route.ts` (165 Zeilen) wird auf ~230 Zeilen wachsen — noch im akzeptablen Bereich. ChatPanel.tsx (2065 Zeilen) bekommt nur ~50 Zeilen Decision-Logic, kein neues Modul.
- **[middle]** MCP/API stabil: `/api/design/cream` existiert bereits als Contract. Neue Body-Parameter (`quick`, `existingHtml`, `changeRequest`) sind **additiv** — brechen keine bestehenden Aufrufe.
- **[far]** README verspricht "agency-level output" — dieser Plan erfüllt dieses Versprechen zum ersten Mal im Standard-Workflow, nicht nur im Opt-in-Agent-Mode. Tech-Debt wird abgebaut, nicht geschaffen.

### 😈 Advocatus Diaboli

- **Failure 1: Cream Quick-Mode ist immer noch zu langsam (60s).** → **Mitigation:** Progress-Feedback ("Art-Direction...", "Generiere HTML...") via simulierte Stufen, wie bei der 10-Design-Batch bewährt. Plus: Quick-Mode als Default, Voll-Modus als "Premium"-Toggle.
- **Failure 2: HTML-Refinement funktioniert nicht für komplexe Änderungen.** → **Mitigation:** Bewusst akzeptiert. HTML-Refinement ist für kleine Änderungen (Farbe, Text, Bild). Bei "Mach ein komplett anderes Layout" muss der User neu generieren. Das ist ehrlicher als ein JSON-Roundtrip, der Qualität zerstört.
- **Failure 3: User will Direct-Manipulation am HTML.** → **Mitigation:** Das bleibt ein JSON-Editor-Feature. HTML ist "Ansicht & Ship", JSON ist "Bearbeiten". Klare Trennung, keine verwirrenden Zwischenzustände.

## Konkrete Implementierung (3 Schritte, ~180 Zeilen)

### Schritt 1: Cream-Erweiterung (~80 Zeilen)
**Datei:** `src/app/api/design/cream/route.ts`

Drei Erweiterungen, alle additiv:

**(a) Quick-Mode:**
```ts
const quick = body.quick === true;
// Phase 2 (Vision-Critique) nur wenn !quick
if (!quick) { for (let round = 1; round <= maxRounds; round++) { ... } }
```
Außerdem: `maxRounds`-Falle beheben — `body.maxRounds !== undefined ? Number(body.maxRounds) : 3` statt `> 0`.

**(b) HTML-Refinement-Pfad:**
Body erweitern: `existingHtml?: string, changeRequest?: string`.
Wenn `existingHtml` vorhanden, baue Refine-Prompt statt Generate-Prompt:
- Nutze `generateHtmlPrompt(brief, changeRequest || message, existingHtml)` — der `existingHtml`-Slot existiert bereits (art-direction.ts:153)
- Quick-Mode default für Refinement (kein Vision-Loop nötig bei kleinen Änderungen)

**(c) Anti-Slop-Lint nach Generate:**
Importiere `lintHtml` aus `anti-slop.ts`. Nach Generate (Phase 1):
- P0-Funde (Indigo, Emoji, Filler) → als `criticalProblems` in den Refine-Prompt injizieren (falls nicht quick)
- Bei quick: P0-Funde nur loggen, nicht blocken

**(d) Graceful Degradation bei Puppeteer-Fehler:**
```ts
try { png = await renderHtmlToPng(html); } 
catch (puppeteerErr) {
  console.warn('[cream] Puppeteer failed, skipping vision-critique:', puppeteerErr);
  break; // Überspringe Vision-Loop, gib ungeprüftes HTML zurück
}
```

### Schritt 2: ChatPanel Decision-Logic (~60 Zeilen)
**Datei:** `src/components/zdesign/ChatPanel.tsx`

**(a) agentMode default für neue Projekte:**
```ts
// Zeile ~712, nach bestehendem useState:
const [agentMode, setAgentMode] = useState(false);

// Effect: Wenn Projekt geladen wird UND kein bestehendes Design hat → agentMode ON
useEffect(() => {
  if (designMode === 'NODE_TREE' && !designTree?.children?.length && !designHTML) {
    setAgentMode(true); // Neues Projekt → Premium-Default
  }
}, [designMode, designTree, designHTML]);
```

**(b) Drei-Wege-Decision in `sendMessage`:**
```
Bestehendes HTML + Änderungswunsch → POST /api/design/cream {existingHtml, changeRequest, quick: true}
Neu-Generierung + agentMode → POST /api/design/cream {message, quick: true}
JSON-Verfeinerung (bestehendes JSON + Änderung) → POST /api/chat (bestehend)
```

**(c) Progress-Feedback:**
- "Art-Direction wird vorbereitet..." (sofort)
- "Generiere HTML-Design..." (nach 2s)
- "Finalisiere..." (nach 40s)
- Bei Voll-Modus: "Vision-Critique Runde 1/3..." etc.

### Schritt 3: Cream Persistenz (~40 Zeilen)
**Datei:** `src/app/api/design/cream/route.ts`

Cream wird selbstständig (wie Agent):

```ts
// Vor return (Zeile 152):

  score, trace, projectId,
  createdAt: assistantMessage.createdAt,

```
